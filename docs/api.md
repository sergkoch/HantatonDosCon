# API

Базовый адрес в разработке: `http://localhost:8080`.

## Приватность истории

История проверок приватна для браузера. Клиент присылает анонимный
идентификатор в заголовке `X-Client-ID` (8–64 символа `A–Z`, `a–z`, `0–9`,
`-`, `_`). **Без заголовка история и отчёты недоступны** (`400 invalid_input`):

- `POST /api/scans` сохраняет скан за этим идентификатором;
- `GET /api/scans` возвращает только его проверки;
- `GET /api/scans/{id}`, `GET /api/scans/{id}/pdf` и
  `GET /api/scans/{id}/gate` отдают `404`, если скан принадлежит другому
  идентификатору;
- `DELETE /api/scans` очищает только его историю;
- номера версий и диффы считаются в пределах одного идентификатора.

Веб-интерфейс хранит идентификатор в `localStorage` и создаёт новый, если
хранилище очистили. Это **приватность, а не авторизация**: кто получил ID,
увидит историю.

Приватные ответы отдают `Cache-Control: no-store` и
`Vary: X-Client-ID, X-Lang`, чтобы браузер и прокси не кэшировали чужие отчёты.

## Язык

Язык ответа выбирается заголовком `X-Lang` (`ru` или `en`), иначе берётся
`Accept-Language`, иначе русский. Язык сохраняется в скане (`lang`) и
фиксирует язык находок, рекомендаций и экспортов: PDF-отчёт строится на языке
скана, CSV собирается в браузере из уже локализованных находок. Изменить язык
старого скана нельзя — он остаётся таким, каким был запущен.

## GET /api/health

Проверка, что сервис жив.

```json
{
  "status": "ok",
  "version": "0.1.0",
  "ai": "missing",
  "time": "2026-11-22T10:00:00Z"
}
```

`ai` принимает `configured` или `missing`.

## POST /api/scans

Запускает проверку.

Запрос:

```json
{
  "url": "https://example.ru",
  "depth": 2
}
```

Правила:

- заголовок `X-Client-ID` обязателен (`400` без него);
- `url` — только `http` или `https`;
- `url` должен вести на публичный адрес: `localhost`, приватные и link-local IP
  отклоняются (`400`, `url must be public`);
- исключение — хосты из `SCAN_ALLOWED_HOSTS` (нужно для локального демо-сайта);
- `depth` — от 1 до 3;
- по умолчанию `1`;
- тело запроса — не больше 1 МиБ (`413`);
- не больше 20 сканов в минуту с одного инстанса (`429`, `Retry-After: 60`).

Ответ `201 Created`:

```json
{
  "id": "0f7f0f2e-6a0b-4a3e-9f4e-7d1b2c3d4e5f",
  "url": "https://example.ru",
  "depth": 2,
  "status": "queued",
  "score": null,
  "stats": { "critical": 0, "warning": 0, "ok": 0 },
  "findings": [],
  "createdAt": "2026-11-22T10:00:00Z"
}
```

## GET /api/scans/{id}

Возвращает скан.

```json
{
  "id": "0f7f0f2e-6a0b-4a3e-9f4e-7d1b2c3d4e5f",
  "url": "https://example.ru",
  "depth": 2,
  "status": "done",
  "version": 2,
  "previousId": "9f8e7d6c-5b4a-4321-8765-fedcba987654",
  "score": 42,
  "pages": 3,
  "checkedLinks": 18,
  "unverifiedLinks": 0,
  "stats": { "critical": 2, "warning": 1, "ok": 1 },
  "ai": {
    "enabled": true,
    "imagesChecked": 6,
    "linksChecked": 8,
    "skipped": 2
  },
  "changes": {
    "added": [],
    "fixed": [
      {
        "id": "f2",
        "code": "LINK_BROKEN",
        "kind": "link",
        "severity": "critical",
        "title": "Битая ссылка",
        "element": "<a href=\"/old\">old</a>",
        "recommendation": "Исправьте адрес ссылки.",
        "wcag": "2.4.4",
        "confidence": 0.82
      }
    ],
    "remaining": 2,
    "scoreDelta": 12
  },
  "findings": [
    {
      "id": "f1",
      "code": "IMG_NO_ALT",
      "kind": "image",
      "severity": "critical",
      "title": "Нет alt у изображения",
      "element": "<img src=\"photo.svg\">",
      "recommendation": "Добавьте описание, что на картинке.",
      "wcag": "1.1.1"
    }
  ],
  "createdAt": "2026-11-22T10:00:00Z"
}
```

`version` — номер проверки этого URL. Первая проверка получает `1`, каждая
следующая — `+1`. `previousId` указывает на предыдущую завершённую проверку.

`changes` сравнивает текущие находки с предыдущей проверкой по паре
`code + element`. В diff попадают только проблемы (`critical` и `warning`);
находки `ok` не считаются:

- `added` — новые проблемы;
- `fixed` — проблемы, которых больше нет;
- `remaining` — сколько проблем осталось;
- `scoreDelta` — изменение оценки относительно предыдущей проверки.

`ai` показывает, сколько элементов реально проверила модель. `confidence` у
находки — уверенность ИИ от 0 до 1; при низкой уверенности критичная находка
не ставится.

Для первой проверки URL `changes` отсутствует.

`status`:

- `queued` — создан;
- `running` — идёт проверка;
- `done` — готово;
- `failed` — ошибка; причина в поле `error`.

`score` — от 0 до 100 или `null`, пока проверка не закончена.

`kind` принимает `image`, `pdf`, `link`, `page`, `form`, `table`.

`pages` — сколько страниц удалось обойти. Если 0, скан получает `failed`.

`checkedLinks` — сколько уникальных ссылок проверили по HTTP.
`unverifiedLinks` — сколько ссылок не удалось проверить: сервер ответил 401/403/429/5xx
или не ответил. Такие ссылки не считаются битыми и не влияют на оценку.

## GET /api/scans/{id}/pdf

Отдаёт PDF-отчёт по скану:

- сайт, версия, дата, оценка;
- сводка critical / warning / ok;
- блок изменений с прошлой проверки;
- находки с рекомендациями и WCAG.

Параметр `lang=ru|en` задаёт язык отчёта; без него берётся язык запроса.
Находки хранятся сразу на двух языках, поэтому PDF можно выгрузить на любом
из них независимо от языка скана.

Ответ: `application/pdf`, файл `report-{id}.pdf`.

## GET /api/scans/{id}/gate

CI-гейт для пайплайна. Возвращает `200`, если скан проходит пороги, и `409`,
если нет: `curl --fail` в таком случае завершится с ненулевым кодом.

Параметры:

- `min_score` — минимальная оценка, `0..100`, по умолчанию `0`;
- `max_critical` — допустимое число критичных находок, `>= 0`,
  по умолчанию `0`.

```bash
curl --fail --silent --show-error \
  "https://not-domain.ru/api/scans/<id>/gate?min_score=80&max_critical=0" \
  -H "X-Client-ID: $ACCESSIBLE_CLIENT_ID"
```

Ответ:

```json
{
  "id": "0f7f0f2e-6a0b-4a3e-9f4e-7d1b2c3d4e5f",
  "url": "https://example.ru",
  "status": "done",
  "passed": false,
  "score": 42,
  "critical": 2,
  "warning": 1,
  "limits": { "minScore": 80, "maxCritical": 0 },
  "reasons": [
    "оценка 42 ниже порога 80",
    "критичных находок 2 больше допустимого 0"
  ]
}
```

Коды:

- `200` — гейт пройден;
- `409` — гейт не пройден; для `queued`/`running` — `error: "not_ready"`,
  для `failed` — `error: "failed"`;
- `400` — неверный `min_score` или `max_critical`;
- `404` — скан не найден или принадлежит другому `X-Client-ID`.

## GET /api/scans

Журнал проверок, новые сверху. Возвращает только сканы текущего
`X-Client-ID`.

Параметры:

- `url` — точный адрес сайта; без него возвращаются все проверки;
- `limit` — от 1 до 100, по умолчанию 20.

```json
[
  {
    "id": "0f7f0f2e-6a0b-4a3e-9f4e-7d1b2c3d4e5f",
    "url": "https://example.ru",
    "status": "done",
    "version": 2,
    "score": 42,
    "stats": { "critical": 2, "warning": 1, "ok": 1 },
    "findings": [],
    "createdAt": "2026-11-22T10:00:00Z"
  }
]
```

`findings` в списке может быть пустым: это краткая история, полный отчёт
запрашивается через `GET /api/scans/{id}`.

## DELETE /api/scans

Удаляет все проверки текущего `X-Client-ID` (только свои, чужие не трогает).

```bash
curl -X DELETE https://not-domain.ru/api/scans \
  -H "X-Client-ID: <идентификатор>"
```

```json
{ "deleted": 3 }
```

Без заголовка `X-Client-ID` возвращает `400` — чтобы случайно не очистить
чужие проверки. В интерфейсе кнопка «Очистить историю» на странице истории
спрашивает подтверждение.

## Ошибки

```json
{
  "error": "invalid_input",
  "detail": "url must be http or https"
}
```

Коды:

- `400` — неверный запрос, приватный или неразрешимый адрес;
- `404` — скан не найден;
- `409` — CI-гейт не пройден или скан ещё не завершён;
- `413` — тело запроса больше 1 МиБ;
- `429` — слишком много запросов;
- `500` — внутренняя ошибка.

## Правила контракта

- Поля не переименовываем без согласования с командой.
- Новые поля добавляем, старые не ломаем.
- Все даты — ISO 8601 UTC.
- Пустые массивы — `[]`, а не `null`.
- Секреты и ключи в ответы не попадают.
