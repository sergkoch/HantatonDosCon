# Разбор задания от 27.11.2026

## Блок 1. Критичные исправления

### Cookie-баннер

- Баннер — компактная карточка шириной до 420 px по центру снизу, а не полоса
  на всю ширину.
- На мобильных — отступы 12 px слева и справа, `transform` отключён.
- Есть крестик и кнопка «Что хранится» с `aria-expanded` и `aria-controls`.
- В раскрывающемся блоке перечислены реальные ключи: `theme`, `locale`,
  `ac.client-id`, `cookie-consent`.
- Текст честно говорит: аналитики, рекламных трекеров и передачи данных
  третьим лицам нет.
- «Принять» сохраняет `cookie-consent=accepted`; после перезагрузки баннер
  не появляется.

### Согласие в футере

- Слева — контакты команды, справа — кнопка «Согласие на cookie» и подпись.
- Кнопка открывает карточку заново, даже если согласие уже принято.
- Почта и телефон — ссылки `mailto:` и `tel:`.
- На мобильных футер складывается в колонку.

### Переходы между страницами

- `html { scrollbar-gutter: stable; }` — контент не сдвигается при появлении
  скроллбара.
- Ленивые страницы показывают скелетон с `min-height: calc(100vh - 220px)`.
- Промисы динамического импорта кешируются; история предзагружается по
  `pointerenter` и `focus`.
- `main` получает фокус с `preventScroll: true`.
- `navigate()` ничего не делает, если путь и query уже совпадают.
- В Vite добавлен `server.watch.ignored = ["**/dist/**"]`.

### Заголовок вкладки

- Router больше не пишет `document.title`.
- Layout считает заголовок по пути и языку: главная, история, отчёт, 404.
- При переключении на English заголовок тоже английский.

### «Как это работает» не с главной

- Ссылка ведёт на `/#how`.
- Если пользователь не на главной, сначала выполняется `navigate("/")`,
  затем `scrollIntoView` и фокус на секцию.
- У секции `tabindex="-1"`, анимация уважает `prefers-reduced-motion`.

### Утечка истории в PostgreSQL

- `Postgres.List` теперь всегда сравнивает `owner_id = $2`, а не только при
  непустом значении.
- Пустой `X-Client-ID` видит только сканы с пустым владельцем.
- В коде оставлен комментарий, почему нельзя возвращать `($2 = '' OR ...)`.

### Таймаут скана

- Перед финальной записью проверяется `ctx.Err()`.
- При истёкшем контексте скан получает `status=failed` и понятную причину,
  оценка не сохраняется как успешная.
- Добавлен ключ `ScanTimeout` в RU/EN.

### Порядок находок

- `findingsBy` сортирует `critical → warning → ok`, затем `created_at`, `id`.
- Два подряд запроса одного скана дают одинаковый порядок.

## Блок 2. Бонусные функции

- **Повторная проверка.** Кнопки в отчёте и в истории вызывают
  `createScan(url, depth)`, показывают busy-состояние и ошибку, не дают
  запустить второй скан одновременно.
- **Аналитика отчёта.** `lib/insights.ts` считает проблемы по типам контента и
  критериям WCAG, игнорирует `ok`, сортирует по частоте, полосы считает от
  максимума. Покрыто unit-тестами.
- **Сводка истории.** Число проверок, средняя оценка (только по числовым
  `score`), сумма critical, дата последней проверки. Покрыто тестами.
- **Экспорт JSON.** `{ schemaVersion: 1, generator, exportedAt, scan }`,
  файл `report-{id}.json`, Blob URL освобождается.
- **CI-гейт.** `GET /api/scans/{id}/gate?min_score=&max_critical=` проверяет
  владельца, отдаёт `409 not_ready` для незавершённых сканов, `200`/`409` для
  `done` и причины провала. В отчёте есть раскрывающийся блок с примером
  `curl`. Покрыто тестами: pass, fail с двумя причинами, чужой владелец,
  `not_ready`, неверный параметр.
- **Управление согласием.** Общее состояние в `lib/cookieConsent.svelte.ts`
  используют и баннер, и кнопка в футере.

## Ограничения

Это не баги, а честные границы текущей версии:

- **Приватность — не авторизация.** История привязана к анонимному
  `X-Client-ID` из `localStorage`. Кто получил идентификатор, увидит историю;
  это ограничение, а не защита аккаунта.
- **OCR не подключён.** PDF без текстового слоя сразу получает `critical`.
  Tesseract в образ не добавлен.
- **HTML-версия PDF не проверяется.** Отчёт не обещает альтернативную версию.
- **Контент на JavaScript не обходится.** Краулер видит серверный HTML.
- **Контраст, клавиатура и ARIA не проверяются.** Это указано в блоке
  покрытия отчёта.
- **PDFium работает в процессе** (WebAssembly). Вызовы сериализованы
  мьютексом и ограничены таймаутом; отдельный контейнер — возможное развитие.
- **Без `DATABASE_URL` история живёт в памяти** и теряется при перезапуске.
- **ИИ необязателен.** Без ключа формальные проверки работают, семантические
  пропускаются.
- **Лимиты.** 20 сканов в минуту с адреса, общий потолок, 50 страниц,
  20 МБ на PDF, 90 секунд на скан.
