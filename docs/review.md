Документ фиксирует, что было исправлено по заданию от 27.11.2026, какие
дефекты нашлись и что сервис честно **не** умеет. Обновляется вместе с кодом.

## Блок 1. Исправленные дефекты

| № | Дефект | Причина | Что сделано |
| --- | --- | --- | --- |
| 1.1 | Cookie-баннер растянут на всю ширину | `position: fixed; inset-inline: 0` | компактная карточка до 420 px по центру, крестик, блок «Что хранится» с реальными ключами |

| 1.7 | Таймаут сохранялся как успешный скан | не проверялся `ctx.Err()` | проверка перед финальной записью, `status=failed`, ключ `ScanTimeout` |
| 1.8 | Порядок находок менялся между запросами | `ORDER BY created_at, id` | `critical → warning → ok`, затем `created_at, id` |

## Ограничения, которые нельзя скрывать

1. **Приватность — это не авторизация.** История привязана к случайному
   `X-Client-ID` в `localStorage`. Кто угодно с этим идентификатором получит
   доступ к сканам; очистка данных браузера = новая пустая история.
2. **PDF без текстового слоя не распознаётся.** OCR (Tesseract) в образе нет,
   поэтому такой файл сразу получает `critical`. Альтернативная HTML-версия
   PDF не проверяется.
3. **JS-контент не проверяется.** Краулер читает HTML, который отдал сервер.
   SPA и ленивые блоки могут выглядеть пустыми.
4. **Контраст, клавиатура и ARIA не входят в оценку.** Отчёт говорит об этом
   прямо в блоке покрытия.
5. **ИИ — усиление, а не приговор.** Низкая уверенность трактуется как
   «требует проверки».
6. **Память вместо БД.** Без `DATABASE_URL` сканы живут в памяти процесса и
   пропадают при перезапуске.
7. **Язык скана фиксируется при запуске.** Находки хранятся на двух языках,
   но интерфейс показывает язык скана; PDF можно выгрузить на любом.

## Что проверять перед защитой

- `bun run check`, `bun run test`, `bun run build` в `client`;
- `go test ./...`, `go vet ./...`, `go build ./...` в Docker;
- живой сценарий: скан демо-сайта, отчёт, повтор, JSON, CI-гейт, cookie;
- клавиатура: skip-link, меню языка, таблицы, футер.
