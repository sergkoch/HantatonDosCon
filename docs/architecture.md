# Архитектура

## Схема

```
Браузер
  │ HTTPS
  ▼
nginx ── Svelte SPA (client/dist)
  │ /api/*
  ▼
Go API (server)
  ├── store      память или PostgreSQL: scans, findings
  ├── crawler    Colly: обход домена, извлечение медиа
  ├── checks     alt, ссылки, заголовки, формы, таблицы
  ├── pdf        go-pdfium в WASM + pdfcpu (OCR — план)
  ├── ai         HTTP-клиент: vision и текст
  └── report     go-pdf/fpdf (PDF), encoding/csv, JSON в браузере
```

## Почему один сервис

На неделе важнее довезти продукт, чем построить распределённую систему.
Один Go-сервис с внутренними пакетами:

- проще запускать;
- проще тестировать;
- меньше точек отказа;
- быстрее деплой.

Микросервисы можно выделить позже, когда появятся реальные причины.

## Пакеты

| Пакет | Что делает |
| --- | --- |
| `internal/api` | HTTP-роуты, валидация, ответы, CI-гейт |
| `internal/store` | память или PostgreSQL, версии и diff |
| `internal/crawler` | обход сайта, извлечение |
| `internal/checks` | проверки и оценки |
| `internal/pdf` | PDF-анализ в WASM (текст, теги, `/Alt`, `Title`, `Lang`) |
| `internal/ai` | vision и текст (необязательный ключ) |
| `internal/report` | PDF на fpdf |
| `internal/config` | переменные окружения |

## Поток данных

1. Пользователь вводит URL и глубину.
2. API создаёт скан со статусом `queued`.
3. Воркер берёт скан и запускает краулер.
4. Краулер собирает страницы, изображения, PDF и ссылки.
5. Проверки создают находки.
6. PDF-анализатор в процессе (PDFium в WASM) смотрит текстовый слой, теги,
   `/Alt`, `Title` и `Lang`. OCR не подключён: PDF без текста — `critical`.
7. ИИ проверяет смысл `alt` и текста ссылок; без ключа шаг пропускается.
8. Скан получает оценку и статус `done`; при таймауте — `failed` без оценки.
9. Интерфейс показывает отчёт, CSV/PDF/JSON скачивается, CI-гейт отвечает
   `200` или `409`.

## Очередь

Без Redis и Kafka. На неделе:

- таблица `scans` со статусом;
- один воркер-горутина;
- `SELECT ... FOR UPDATE SKIP LOCKED` или простой мьютекс;
- таймаут на скан.

Если время позволит — несколько воркеров, но не больше 3.

## Безопасность

- Сканируем только разрешённые сайты.
- `robots.txt` уважаем.
- SSRF: блокируем приватные IP, `localhost`, metadata-адреса.
- Таймауты и лимиты: 50 страниц, 20 МБ на файл, 30 секунд на запрос.
- PDF-анализатор работает в процессе через PDFium в WASM: без CGO и
  `libpdfium.so`; вызовы сериализованы мьютексом, таймаут и паника не
  оставляют скан в `running`.
- Секреты — только в переменных окружения.
- Приватность истории — `X-Client-ID`; это не авторизация, а анонимная
  привязка к браузеру. Пустой идентификатор видит только свои (пустые) сканы.

## Направления работ

Задачи не привязаны к людям. Команда сама решает, кто что берёт.

- **Интерфейс:** лендинг, форма, экран прогресса, отчёт, фильтры, CSV.
- **API и данные:** роуты, store, миграции, тесты.
- **Краулер:** Colly, извлечение медиа, проверки `alt` и ссылок.
- **PDF:** go-pdfium в WASM, текстовый слой, теги, `/Alt`, `Title`, `Lang`;
  OCR — отдельная задача-план.
- **ИИ:** vision по картинкам, текст ссылок, кэш, деградация.
- **Данные и QA:** демо-сайт, тест-корпус, e2e, документация.
- **Деплой:** Docker, nginx, домен, TLS.

## Границы

- `internal/pdf` и ключи ИИ трогаем только с ответственным, которого выбрала
  команда.
- Сервер и DNS — только с ответственным за деплой.
- В `main` — только через PR.
- Автор не проверяет сам себя.
- Секреты не коммитим.
