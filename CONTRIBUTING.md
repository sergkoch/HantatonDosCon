# Как работать в команде

## Главное правило

Одна задача = один issue = одна ветка = один PR.

## Ветки

Название ветки:

```
task/<номер>-<короткое-название>
```

Примеры:

```
task/12-scan-form
task/18-csv-export
task/21-pdf-text-layer
```

## Коммиты

Пишем коротко и по делу:

```
feat: add scan form
fix: handle empty alt
docs: describe api
test: cover score calculation
```

Не пишем «update», «fix», «ещё немного».

## Pull Request

В PR обязательно:

- что сделано;
- зачем;
- как проверить;
- скриншот, если менялся интерфейс;
- `Closes #<номер issue>`.

Шаблон уже есть в `.github/pull_request_template.md`.

## Проверка

Перед PR:

```bash
cd server
go vet ./...
go test ./...

cd ../client
bun run check
bun run test
bun run build
```

## Ревью

- Автор не проверяет сам себя.
- Нужен хотя бы один другой участник.
- Если есть замечания — исправляем в той же ветке.
- Merge делает не автор: проверяющий или дежурный, после одобрения и зелёного CI.

## Запреты

- Прямой push в `main`.
- Секреты, пароли и ключи в коде.
- `console.log`, `TODO`, `any`, `@ts-ignore` в `main`.
- Чужие ветки без разрешения.
- Файлы из `node_modules`, `dist`, `.env`.

## Если застрял

1. 15 минут пробуешь сам.
2. Пишешь в чат: что делал, что получилось, что не получилось.
3. Прикладываешь текст ошибки и скриншот.
4. Не сидишь молча час.

## Ежедневный ритуал

- 10 минут утром: стендап по `docs/standup.md`.
- 10 минут вечером: демо того, что готово.
- 5 минут: что мешало и что меняем завтра.
